Anyflawa Geospatial Matchmaking & Real-Time Chat

A high-performance location-aware social matchmaking backend utilizing Redis Geospatial indexing and MongoDB 2dsphere compound queries for sub-5ms proximity candidate discovery and scalable bi-directional WebSocket messaging.

1. Executive Summary & Spatial Complexity

In location-aware mobile applications, computing geometric distances between tens of thousands of moving coordinates directly in traditional databases quickly causes CPU exhaustion. Calculating spherical trigonometry across millions of candidate pairs produces prohibitive database latency.

To resolve this, I engineered a two-tier spatial query pipeline:

  • Tier 1: In-Memory Redis Geospatial Index: Mobile coordinates are indexed via Redis GEOADD. Nearby candidate user IDs within configurable radii (1km to 50km) are filtered in microseconds using GEOSEARCH.
  • Tier 2: MongoDB 2dsphere Batch Query: The candidate IDs are piped to MongoDB with compound indexes to apply rich demographic filters (age, interests, preferences) in a single indexed query.

2. Real-Time Chat & Presence Architecture

Matched users communicate over a scalable WebSocket pipeline featuring:

  • Ephemeral Presence & Typing Indicators: Heartbeat liveness and typing states are tracked exclusively via Redis key TTLs without database writes.
  • Offline Message Queuing & Push: When a recipient is offline, messages are persisted in MongoDB and dispatched via Firebase Cloud Messaging (FCM) / Apple APNs.
  • Direct S3 Pre-Signed Uploads: Multimedia attachments (photos, voice notes) upload directly to AWS S3 using short-lived pre-signed URLs, relieving backend servers from handling large file streams.
