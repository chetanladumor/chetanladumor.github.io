Anyflawa Geospatial Matchmaking & Real-Time Chat

A high-performance location-aware social matchmaking backend utilizing Redis Geospatial indexing and MongoDB 2dsphere compound queries for sub-5ms proximity candidate discovery and scalable bi-directional WebSocket messaging.

1. Executive Summary & Spatial Complexity

In location-aware mobile applications, computing geometric distances between tens of thousands of moving coordinates directly in traditional databases quickly causes CPU exhaustion. Calculating spherical trigonometry across millions of candidate pairs produces prohibitive database latency.

To resolve this, I engineered a two-tier spatial query pipeline:

  • Tier 1: In-Memory Redis Geospatial Index: Mobile coordinates are indexed via Redis GEOADD. Nearby candidate user IDs within configurable radii (1km to 50km) are filtered in microseconds using GEOSEARCH.
  • Tier 2: MongoDB 2dsphere Batch Query: The candidate IDs are piped to MongoDB with compound indexes to apply rich demographic filters (age, interests, preferences) in a single indexed query.

2. Real-Time Chat & Matchmaking Lifecycle

The platform orchestrates geospatial discovery and real-time interaction across four decoupled lifecycle phases:

Phase 01

Geospatial Ingress & Proximity Filtering

< 5ms Redis GEOSEARCH
📍 Coordinate Ingress

Mobile app transmits lat/long coordinates on movement; indexed into memory using Redis GEOADD.

🔍 Fast Radius Search

GEOSEARCH extracts nearby user IDs within a 1km–50km radius in microseconds without disk I/O.

🎯 Compound Filter

Pipes candidate IDs into MongoDB compound indexes to filter demographic preferences, age, and interests.

↓
Phase 02

Atomic Swipe & Mutual Match Engine

Sub-10ms Match Detection
👆 Swipe Action

Client submits like/pass swipe event via WebSocket, buffered into user interaction Redis sets.

⚡ Mutual Match Check

Executes atomic SISMEMBER test to verify if target user previously liked the caller.

🎉 Instant Dual Broadcast

On mutual match, creates chat room and broadcasts celebratory match payloads simultaneously to both devices.

↓
Phase 03

Ephemeral Presence & Typing Indicator Loop

Zero Database Writes
💓 Socket Heartbeat

Client transmits 25-second heartbeats refreshing Redis key TTLs to track live online/offline presence.

💬 Typing Indicators

Active typing events emit over Redis Pub/Sub channels with 5-second automatic TTL expiration.

🔋 Mobile Battery Saver

Throttles redundant presence updates to minimize mobile radio wakeups and prolong device battery life.

↓
Phase 04

In-Flight Chat Delivery & Push Notification

Sub-100ms Delivery SLA
🚀 Real-Time Socket Egress

Directly delivers messages to connected recipient socket room with client-side read-receipt confirmation.

📲 FCM / APNs Push Fallback

If recipient is offline, enqueues push notification through Firebase Cloud Messaging and Apple APNs.

☁️ Direct S3 Media Pre-Sign

Voice notes and photos upload directly to AWS S3 via pre-signed URLs, keeping server bandwidth free.
