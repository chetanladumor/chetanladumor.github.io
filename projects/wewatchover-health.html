WeWatchOver – Wearable Biometric Monitoring & Alerting

A high-reliability production IoT backend processing continuous real-time biometric streams (Heart Rate, SpO2, Body Temp, GPS) from Fitbit, Oura Ring, and E88 smartwatches, paired with rule-based automated Twilio SMS emergency alerts.

1. Executive Summary & Patient Safety Scope

The WeWatchOver (GuardMe) platform provides continuous health and safety monitoring for elderly, post-operative, and high-risk patients. Connected smartwatches and wearable rings stream medical telemetry 24/7. When dangerous anomalies occur (such as sudden cardiac tachyarrhythmia, oxygen desaturation, or sudden falls), the backend triggers automated emergency protocols.

The core architecture guarantees zero telemetry data loss, high-frequency timeseries deduplication, and resilient integration with native iOS and Android companion apps.

2. Real-Time Telemetry Pipeline & Alert Workflow

Phase 01

Continuous Edge Ingestion & BLE Sync

5-Sec Mobile Ingress Buffer
⌚ Wearable Telemetry

Fitbit, Oura, and E88 sensors stream HR, SpO2, skin temp, and accelerometer data via BLE to the mobile app.

📶 Gateway Streaming

Mobile app packages telemetry and streams over TLS WebSocket / HTTPS to the Node.js ingestion gateway.

⚡ In-Memory Buffering

Telemetry packets buffer into Redis sorted sets, absorbing intermittent mobile cellular network drops without packet loss.

↓
Phase 02

In-Memory Anomaly Detection & Rule Checks

Sub-10ms Rule Engine
❤️ Cardiac Thresholds

Evaluates acute tachycardia (> 130 BPM) or bradycardia (< 45 BPM) against customized patient baselines.

🫁 Hypoxemia & Fall Vector

Detects blood oxygen drops (SpO2 < 90%) and sudden 3-axis accelerometer shock vectors characteristic of physical falls.

🧹 Noise De-glitching

Applies a 3-point rolling median filter to suppress motion artifacts and transient false positives before tripping alarms.

↓
Phase 03

Multi-Channel Priority Emergency Dispatch

< 2s Critical Alert SLA
🚨 Twilio SMS Escalation

Dispatches priority emergency SMS with vital reading snapshot and dynamic Google Maps location link to caregivers.

📞 Automated IVR Calling

If SMS unacknowledged within 60 seconds, automated phone call escalation dials primary contacts to ensure response.

🗺️ Precision Geocoding

Binds latest GPS latitude/longitude and battery status into emergency ticket for first responders and family.

↓
Phase 04

Timeseries Persistence & Dashboard Streaming

Sub-100ms Live Telemetry
📊 Socket.IO Live Fan-Out

Normal and anomalous vitals stream directly to doctor and caregiver dashboard views with sub-100ms UI latency.

🔔 Visual & Audio Alarms

Tripped anomalies trigger flashing red workstation alerts with persistent audio tones until physician clears ticket.

💾 Timeseries Archiving

Flushes Redis telemetry in micro-batches to MongoDB timeseries collections with 90-day automated TTL indexing.

3. Key Engineering Challenges Solved

1

High-Frequency Timeseries Ingestion

Wearable sensors stream heart-rate readings continuously. To prevent database I/O saturation, telemetry writes are buffered in Redis memory queues and flushed to MongoDB using bulk writes with TTL indexes for automated archiving.

2

Sub-2-Second Emergency Notification

In critical medical incidents, latency is vital. The threshold evaluation runs in memory upon packet ingestion. If thresholds breach, the Twilio REST API request executes with priority concurrency, delivering emergency SMS alerts within 2 seconds of detection.

3

Mobile Reconnect & Offline Sync

Collaborated with iOS and Android teams to establish resilient reconnect protocols, enabling companion apps to cache telemetry locally during transient cellular dead-zones and flush back-dated readings upon reconnect without data corruption.
