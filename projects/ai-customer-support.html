Multi-Agent AI Customer Support: Hybrid RAG & pgvector

An enterprise AI customer service platform combining PostgreSQL pgvector HNSW indexing, sparse lexical GIN search, Reciprocal Rank Fusion reranking, and multi-agent intent routing for hallucination-free automated support.

1. Executive Summary & Motivation

Standard semantic vector search alone often fails in enterprise customer support: pure cosine distance struggles to match exact serial numbers, product SKUs, and specific alphanumeric error codes. Conversely, traditional keyword search fails to interpret conversational nuance and user intent.

I engineered a production-grade Hybrid RAG pipeline in PostgreSQL that unifies dense semantic embeddings with sparse lexical indexing, eliminating hallucinations and ensuring answers are strictly grounded in verified enterprise documentation with traceable citations.

2. The 6-Stage Hybrid RAG Pipeline

1

Query Rewriting & Intent Distillation

Customer questions often contain conversational clutter. An ultra-fast local LLM step distills noisy user messages into search-optimized queries while extracting named entities (order IDs, product models, error codes).

2

Multi-Tenant Hard Filtering

Before executing any vector calculations, the database query applies hard SQL filters on tenantId and role-based access control. Pre-filtering guarantees enterprise data boundary isolation while reducing memory search space.

3

Simultaneous Hybrid Retrieval (Vector + Keyword)

Executed within a single PostgreSQL query utilizing Common Table Expressions (CTEs):

  • Dense Semantic Search: Uses pgvector with an HNSW (Hierarchical Navigable Small World) index to measure cosine similarity across embeddings.
  • Sparse Lexical Search: Uses PostgreSQL's GIN index on a precomputed search_vector column to capture exact part numbers and SKU codes.
4

Reciprocal Rank Fusion (RRF) Reranking

Because cosine distance and full-text TF-IDF scores operate on incompatible mathematical scales, raw score addition causes severe bias. The system applies Reciprocal Rank Fusion, evaluating candidates purely by their relative ranking in both candidate lists to generate a balanced, scale-invariant top candidate set.

5

Cross-Encoder Re-Ranking Stage

The top candidate chunks are processed through a cross-encoder model. Unlike bi-encoders that process queries and documents separately, the cross-encoder performs joint token-level attention between query and context, isolating the top 2 most authoritative chunks.

6

Grounded Generation with Traceable Citations

The curated context is assembled into a token-bounded prompt with strict grounding constraints. Responses stream to the user via Server-Sent Events (SSE), complete with clickable citation chips linking directly to source article IDs.

3. Multi-Agent Routing Architecture

Beyond knowledge retrieval, the platform employs specialized sub-agents:

  • Intent Router Agent: Classifies customer requests into Order Tracking, Billing & Invoices, or General Technical Inquiries.
  • Order Agent: Equipped with Zod-validated database tool calls to look up real-time shipment milestones, tracking numbers, and delivery ETAs directly from PostgreSQL.
  • Billing Agent: Handles refund requests, invoice lookups, and payment gateway status verification through Stripe API webhooks.

4. Key Engineering Decisions

⚙️ Why HNSW Over IVFFlat?

While IVFFlat requires periodic retraining and degrades query recall under high update volume, HNSW (Hierarchical Navigable Small World) constructs a multi-layer graph index. It enables fast logarithmic query traversal with high recall (>98%) and supports immediate real-time vector inserts without maintenance downtime.
