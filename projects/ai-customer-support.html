Multi-Agent AI Customer Support: Hybrid RAG & pgvector

An enterprise AI customer service platform combining PostgreSQL pgvector HNSW indexing, sparse lexical GIN search, Reciprocal Rank Fusion reranking, and multi-agent intent routing for hallucination-free automated support.

1. Executive Summary & Motivation

Standard semantic vector search alone often fails in enterprise customer support: pure cosine distance struggles to match exact serial numbers, product SKUs, and specific alphanumeric error codes. Conversely, traditional keyword search fails to interpret conversational nuance and user intent.

I engineered a production-grade Hybrid RAG pipeline in PostgreSQL that unifies dense semantic embeddings with sparse lexical indexing, eliminating hallucinations and ensuring answers are strictly grounded in verified enterprise documentation with traceable citations.

2. Hybrid RAG Inference Lifecycle & State Engine

Phase 01

Query Ingress, Intent Distillation & Multi-Tenant Pre-Filter

< 40ms Ingress & Parse
💬 Noisy Query Cleanup

Local LLM step strips conversational filler and extracts key entities (order numbers, SKU codes, error IDs).

🔒 Hard Tenant Boundaries

Applies strict SQL pre-filtering on tenantId and role policies, eliminating cross-tenant leakage.

⚡ Embedding Generation

Generates 1536-dimensional dense query vector via localized embedding pipeline.

↓
Phase 02

Simultaneous Dual Retrieval: HNSW pgvector + Lexical GIN

< 15ms Parallel Query
🧠 Dense Semantic Search

Executes cosine distance calculation on pgvector using multi-layer HNSW graph indexing (>98% recall).

🔍 Sparse Keyword Matching

Runs BM25-equivalent full-text search against PostgreSQL GIN indexes on precomputed search_vector tsvectors.

⚡ Unified CTE Query

Combines vector similarity and lexical ranking inside a single SQL query with Common Table Expressions.

↓
Phase 03

Reciprocal Rank Fusion & Cross-Encoder Attention

< 50ms Re-Ranking SLA
⚖️ Scale-Invariant RRF

Merges disparate vector scores and lexical TF-IDF ranks using reciprocal rank fusion, eliminating score bias.

🎯 Cross-Encoder Attention

Performs joint token-level query-document attention over the top candidates to isolate the 2 most authoritative chunks.

🛡️ Hallucination Guard

Rejects context chunks scoring below 80% relevance threshold, prompting fallback to live human agent handoff.

↓
Phase 04

Grounded LLM Generation & SSE Stream Egress

< 100ms Time-to-First-Token
📜 Grounded Prompts

Injects retrieved chunks into strict system prompt templates enforcing verifiable factual assertions.

🌊 Real-Time SSE Stream

Streams markdown tokens back to the user via Server-Sent Events (SSE) for zero perceived interface lag.

🏷️ Traceable Citation Chips

Appends interactive citation badges linking directly to specific knowledge base doc IDs and change histories.

3. Multi-Agent Routing Architecture

Beyond knowledge retrieval, the platform employs specialized sub-agents:

  • Intent Router Agent: Classifies customer requests into Order Tracking, Billing & Invoices, or General Technical Inquiries.
  • Order Agent: Equipped with Zod-validated database tool calls to look up real-time shipment milestones, tracking numbers, and delivery ETAs directly from PostgreSQL.
  • Billing Agent: Handles refund requests, invoice lookups, and payment gateway status verification through Stripe API webhooks.

4. Key Engineering Decisions

⚙️ Why HNSW Over IVFFlat?

While IVFFlat requires periodic retraining and degrades query recall under high update volume, HNSW (Hierarchical Navigable Small World) constructs a multi-layer graph index. It enables fast logarithmic query traversal with high recall (>98%) and supports immediate real-time vector inserts without maintenance downtime.
